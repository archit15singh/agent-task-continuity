# Reporting standards audit

The paper describes engineering research on a prototype, with automated benchmark-style comparisons, controlled process faults, and exploratory model diagnostics. Historical parents, upstream references, and scripted runs serve as controls. The timing exercise involved scripts and no human participants. [SIGSOFT Engineering Research standard](https://www2.sigsoft.org/EmpiricalStandards/docs/standards#engineering-research-aka-design-science) · [SIGSOFT Benchmarking standard](https://www2.sigsoft.org/EmpiricalStandards/docs/standards#benchmarking-of-software-systems)

| Practice | Application to this study |
|---|---|
| Describe the artifact, assumptions, and alternatives | Explain which mechanisms ship with the CLI and which live in the receiver fixtures. State the shared Git and local SQLite assumptions. Treat manual Git plus selected files as the transport comparator. Identify the brief-only condition as a transport control that had no reconstruction worker. Framework comparisons remain conceptual. |
| Define the workload, unit, and outcome before interpreting counts | Identify pinned tasks, attempts, injected faults, operation receipts, and behavior probes as separate units. Define the pass criteria for restored artifacts, verified code, and confirmed effects. Describe deadlines and the configuration changes between rounds. Counts from repeated probes on one helper describe the probe set. |
| Record protocol history and retain deviations | Keep the original Git-committed protocol, its amendments, and the evidence from failed setup or model runs. Distinguish prespecified comparisons, scripted qualification checks, and follow-ups motivated by prior observations. Git commits provide the protocol history. The repository records no independent registration. |
| Explain claim boundaries and competing interpretations | Separate source checks from complete snapshot recovery and successful process exit from correct edits. Preserve controls that reject incomplete repairs and accept equivalent implementations. Describe the interactions among models, endpoints, prompts, and tool surfaces. The live sample supports descriptive feasibility findings. Stability estimates, framework rankings, and causal productivity claims require additional runs or participants. |
| Provide an exercisable artifact | Link protocol, inputs, grader, receipts, dependency instructions, and preserved failures from the paper. Make an offline receipt audit and a fresh deterministic run easy to distinguish. Explain the prerequisites for live inference and the limits of verifying historical raw logs with public summaries and hashes. |

The protocol practices follow the Center for Open Science guidance on distinguishing planned work from exploration and recording changes. The artifact practices follow ACM venues that apply the ACM policy. They distinguish an accessible package, a documented and exercisable artifact, and results obtained by an independent team. [Center for Open Science preregistration guidance](https://www.cos.io/initiatives/prereg) · [ACM SIGIR artifact guidance](https://sigir.org/general-information/acm-sigir-artifact-badging/) · [ACM SIGSIM artifact review criteria](https://sigsim.acm.org/conf/pads/2026/blog/artifact-evaluation/)

## Residual limits

- The study covers three Python repositories on one host, with small live sample sizes and public changes that may be present in model training data. Repeated fixture faults validate the specified boundaries under controlled conditions. No operator comparison, hosted effect-receiver experiment, or independent-team reproduction is recorded.
- The public package includes scripts, pinned revisions, and machine-readable receipts. Historical live prompts, raw output, and candidate source are not consistently preserved as public inputs. Hashes constrain checks on matching bytes when available. Provider versions, model availability, and stochastic generation constrain exact live replay.
- GitHub provides version-addressable public access. A preservation archive with a persistent identifier and an explicit license would improve reuse. Artifact review and badges require venue processes separate from this author-side audit. [ACM SIGSIM artifact review criteria](https://sigsim.acm.org/conf/pads/2026/blog/artifact-evaluation/)
