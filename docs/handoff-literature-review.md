# What research says about agent handoff and crash recovery

Focused full-text review for Agent Task Continuity, November 26, 2026. Coverage follows the four proposed next steps. The sources include peer-reviewed research, research preprints, and one project-authored whitepaper, identified below. The project measurements come from the existing [paper](paper.md) and [experiment receipts](../evidence/README.md).

## The project question

A takeover can succeed at four different levels. The workspace is intact. The replacement understands what remains to do. It completes a change that passes an independent grader. An external effect is confirmed once even if the original worker disappears. Our three repository cases established file transfer. The loopback provider established managed recovery for six injected faults. The 9B OpenCode run established zero verified completions under the tested deadline. Each result calls for a different follow-up.

## 1. Freeze a task and measure takeover fairly

**Handoff Debt** is the closest coding-specific comparison. The authors used 181 intermediate repository states from 75 SWE-bench Verified issues, paired each state across four handoff views, and tried three successor models. The raw trace reduced median agent events by 57–59% and improved solve rates by 6.1–14.9 percentage points. Summary and structured notes reduced median events too, while significant solve-rate gains from notes appeared only for Devstral. Agent events measure interaction, and these numbers come from the authors' tested models and harness. §§2–5 and appendix. [Handoff Debt, 2026 preprint](https://arxiv.org/html/2606.02875v1)

**ContinuityBench** compares uninterrupted runs with restarts at controlled step boundaries across three agent benchmarks. Average success dropped from 41.7% to 28.0% in the interrupted settings. A structured summary beat summary plus action history in 11 of 18 settings. The frozen environment and step-boundary interruption isolate resumption. In-flight tool failures and concurrent edits call for separate tests. §§3–5. [Gulati, ICML CTB workshop 2026](https://openreview.net/pdf/93d0bd39f66f01a5565ae496208d39676dde78ec.pdf)

**HSC-Bench** splits takeover into 300 repository evidence tasks and 739 synthetic continuation tasks. It holds the receiver, handoff point, and visible token count fixed when comparing structured state with a recent transcript. Structured state improved repository evidence recovery for all six receivers. For continuation, gains depend on the scoring criteria. In one subset where both formats exposed a completed update, receivers repeated it twice in 114 structured-state runs and zero times in the transcript arm. Record completion for the agent and enforce consequential actions at the runtime boundary. §§3–5, including §5.4 and Table 4. [Li et al., 2026 preprint](https://arxiv.org/html/2610.36523)

**What Does a Harness Buy? Tokens, Mostly.** The authors crossed seven models with Claude Code, mini-SWE-agent, and OpenCode, and ran unchanged controls again. On their hard45 set, harness swaps and identical reruns each flipped a median 13% of task outcomes, while model swaps flipped 26%. Particular model–harness pairings still had measurable differences. Appendix H also isolates an OpenCode output-cutoff pattern in one larger Qwen model. Copying a resume prompt produced no detectable improvement on the selected cases and raised input use. This supports an unchanged rerun and careful cutoff diagnostics. The reported output cutoff is a separate mechanism from our `compaction.failed` result. §§3–5, Appendix H. [Liu and Han, 2026 preprint](https://arxiv.org/html/2610.04433v2)

**Harness-Bench** evaluated model–harness configurations under shared environments and budgets while retaining native tools, prompts, and execution loops. The authors scored partial quality and full delivery separately. On 274 general tasks, about 51% earned at least 0.8 credit and about 26% earned full credit. This supports recording progress milestones separately from a final pass. Exact rates mix task families, configurations, and grading rules. §§3–5. [Yao et al., 2026 preprint](https://arxiv.org/html/2605.27922)

**SWE-bench** provides a simple grading pattern. A candidate must pass tests that fail on the original revision and tests that already pass there. On Packaging, a green upstream suite alone leaves the missing behavior untested. Keep the targeted grader, the carried reproduction, and the upstream regression suite. §2 and Appendix A.4. [Jimenez et al., ICLR 2024](https://arxiv.org/html/2310.06770)

**What to change here.** First make an immutable Packaging diagnostic checkpoint. Save the Git revision, patch, selected artifacts, handoff note, tool permissions, runtime versions, model settings, and context budget. Change one question at a time:

- **Harness check.** Run the same artifact and same exact model/provider through two harnesses where supported, with repeated unchanged runs for orientation. If model/provider parity is unavailable, call it a configuration comparison.
- **Handoff check.** In one harness and model, compare checkout alone, checkout plus the same concise note, and optionally a scrubbed trace. Start with a bounded note and access to exact evidence by file path or revision. Raw traces can save rediscovery while costing more context upfront. Record the cost of creating the note as well as reading it.
- **Grade in stages.** Capture restored bytes, first relevant read, repeated or failed calls, first applied edit, targeted behavior, regression suite, and termination reason. Use separate diagnostic cases when iterating and fresh cases for any broader claim. Include an already-solved checkpoint in a later round to detect unnecessary edits or regressions.

A single replay is valuable for locating a defect. Repeatable success on fresh tasks is a higher bar. [AI Agents That Matter, §§2, 5–6](https://arxiv.org/html/2407.01502)

## 2. Separate compaction failure from editing failure

**Compact-Bench** takes the same pre-compaction history, repository snapshot, and continuation agent, then changes the summary. Among 22 repairs already validated as solvable using the full history, between 1 and 14 became stable failures across 14 summarizers. That denominator describes a specific subset. The experiment measures the consequences of a summary that reaches the next agent. In our Packaging control, OpenCode returned an error during compaction. First reproduce whether a summary is even produced. Then test whether it preserves the facts required for continuation. §§3–4, Table 2. [Compact-Bench, 2026 preprint](https://arxiv.org/html/2610.31710v1)

**The Complexity Trap** compares raw history, replacing old tool observations with placeholders, and LLM summarization. With Qwen3-Coder 480B on SWE-bench Verified, raw history scored 53.4% at $1.29 per instance, observation masking scored 54.8% at $0.61, and summarization scored 53.8% at $0.64. Other backbones behaved differently. Keeping durable evidence available and shrinking the model's working view is an inexpensive experimental arm. §3–4, Table 1. [The Complexity Trap, 2025 preprint](https://arxiv.org/html/2508.21433v1)

**SWE-agent and SWE-Edit** deal directly with code tools. SWE-agent tests narrower search, bounded file views, and edit feedback. SWE-Edit separates exploratory reading from patch formatting. On its tested setup, the combined system raised edit-application success from 93.4% to 96.9% and task resolution from 69.9% to 72.0%. The smaller movement in task resolution is why the Click fixture should grade both whether a patch applies and whether it solves the task. [SWE-agent, NeurIPS 2024, §§3 and 5.1](https://arxiv.org/html/2405.15793) · [SWE-Edit, 2026 preprint, §4.2](https://arxiv.org/html/2604.26102)

**What to change here.** Run two small fixtures before launching a full repository matrix. For Packaging, replay a fixed or sanitized synthetic history and log compaction entry, configured budget, provider finish/error reason, summary return, and first resumed action. A rejected request, an incomplete summary, and a successful summary that drops a needed fact are separate outcomes. For Click, use one known file and exact target text. Compare the existing replacement tool with a scoped patch method and classify match failures separately from grader failures. The literature supports these tests. The internal cause of our previous compaction error is still open.

## 3. Measure whether a person benefits in Herdr

**Resumption Strategies for Interrupted Programming Tasks** analyzed 9,899 IDE sessions from 86 programmers and surveyed programmers about how they resume. About 10% of sessions with edits reached the first edit within one minute. In the detailed Visual Studio navigation subset, 91 of 1,213 editing sessions made a change without navigating to other methods. The logged gaps are a proxy for interruptions, and first edit is a proxy for productive work. §§3–5. [Parnin and Rugaber, Software Quality Journal 2011](https://chrisparnin.me/pdf/parnin-sqj11.pdf)

**Evaluating Cues for Resuming Interrupted Programming Tasks** used a counterbalanced within-person trial with 14 usable participants. In three small maintenance tasks, each automatic-cue condition completed 7/14 tasks, compared with 4/14 using notes alone. The completion evidence was weak and timing differences were inconclusive. The useful idea is to compare cues that recover concrete work state, such as recent changes and locations, against a plain note. [Parnin and DeLine, CHI 2010, pp. 97–101](https://chrisparnin.me/pdf/cues-chi09.pdf)

**Using Task Context to Improve Programmer Productivity** found that Mylar's task-focused view improved a log-based edit-to-selection proxy in its retained 16-person field sample. It tested a browsing-effort proxy with strong attrition. A separate randomized study of real open-source maintenance illustrates how to measure actual task duration and include review and cleanup. The 2026 follow-up documents difficulties attributing time with concurrently running agents. [Kersten and Murphy, FSE 2006, §§5.3–5.5](https://www.cs.ubc.ca/~murphy/papers/mylar/2006-11-mylar-fse.pdf) · [Becker et al., 2025, §§2.4 and 3.2](https://metr.org/Early_2025_AI_Experienced_OS_Devs_Study-paper.pdf) · [METR measurement update, 2026](https://metr.org/blog/2026-02-24-uplift-update/)

**Task Interruption in Software Development Projects** combined 4,910 retrospective task records from one company with a 132-developer survey. Interruption source, timing, and task context tracked disruption, and perceived effects could differ from the record. Label these factors in the Herdr pilot. §§3–5. [Abad et al., EASE 2018](https://arxiv.org/html/1805.05508)

**What to change here.** Use distinct comparable real tasks and alternate manual and managed conditions. Reusing an identical task for the human comparison introduces learning. Log capture effort, time to workspace-ready, time to the first independently useful action, human active time, agent wait, and time through review or cleanup. Record interruption type and duration. Compare against a competent manual workflow with Git export, selected files, and good notes. A small personal pilot gives local product evidence.

## 4. Take side-effect recovery past the loopback fixture

**RIFL** makes safe retries depend on four properties. An operation has a stable identity. The service stores the mutation and its completion record atomically. Retries can find that record after failover. Retention outlasts legitimate retries. A client-side intent ledger can preserve what it asked the service to do. Whether the remote effect happens once depends on the service contract. §§3–4. [Lee et al., SOSP 2015](https://web.stanford.edu/~ouster/cgi-bin/papers/rifl.pdf)

**Durable Functions and Netherite** show how causal commits preserve consistent workflow history. They give an example where retrying nondeterministic workflow logic can emit a different action on replay, and per-action idempotency still permits both. Persist the chosen request, target, payload, and key before dispatch. Record observed results and recover from the record. Provider cooperation still matters for irrevocable external actions. §§3.3–3.5 and 4. [Burckhardt et al., Durable Functions research](https://arxiv.org/pdf/2103.00033)

**Chubby, Sagas, and lineage-driven fault injection** identify three useful boundaries. A delayed request from an old lock holder can arrive after a transfer, so the recipient must validate the generation to enforce a fence there. Compensation in a saga is a new semantic action, and intervening effects can remain visible. Lineage-driven testing starts from a successful outcome and injects failures at causal dependencies instead of choosing only random kill points. [Chubby, OSDI 2006, §2.4](https://static.usenix.org/event/osdi06/tech/full_papers/burrows/burrows.pdf) · [Sagas, SIGMOD 1987](https://www.cs.princeton.edu/techreports/1987/070.pdf) · [Lineage-driven Fault Injection, SIGMOD 2015](https://people.ucsc.edu/~palvaro/molly.pdf)

**OpenCheckpoint**, a project-authored whitepaper, is a close adjacent design. Its mock payment experiments with capable handoff producers recorded 0/36 violations for summaries or structured checkpoints and 12/12 without a handoff. Format effects were harder to establish once both treatments hit zero. In the 20-task coding arm, observed solve-rate differences were inconclusive. In its single long-session experiment, a shorter handoff saved destination inference cost. Accounting for authoring reversed that cost comparison for one continuation in the Claude arm. These findings support measuring both tool-use and end-to-end cost and keeping machine-checked pending operations in the task record. §§4–5. [OpenCheckpoint whitepaper, 2026](https://opencheckpoint.org/opencheckpoint-whitepaper.pdf)

**What to change here.** Pick one sandbox action whose exact final state can be checked independently. GitHub reference creation in a disposable repository is a close use case: use a deterministic reference name, pin the intended commit, lose the response after acceptance, and read the reference back after takeover. Count an existing reference with the intended SHA as convergence, and a different SHA as conflict. A response code alone is insufficient. Test a delayed prior-owner request separately from the lost-response case. A single unchanged ref measures final state convergence. Claims about provider deduplication or fencing require a contract and observations at the provider boundary. Keep an explicit unknown state when the result cannot be established. [GitHub REST API for Git references](https://docs.github.com/en/rest/git/refs#create-a-reference)

## How this changes the order

1. **Build the cheap diagnostics and freeze Packaging together.** The fixture makes the failure observable. The frozen checkpoint stops changing inputs between runs.
2. **Run the controlled takeover.** Start with an unchanged repeat, then change the handoff or the harness while holding the other fixed.
3. **Try the actual Herdr workflow.** Compare against a competent manual handoff and measure active human time through review.
4. **Test one independently observable external effect.** Keep provider guarantees distinct from the guarantees already demonstrated at the managed local boundary.

The current project has stronger evidence for restoring a workspace and reconciling a controlled effect than for a replacement agent reliably finishing the task. The papers provide ways to test the missing links with small experiments.
